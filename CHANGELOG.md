# Changelog

All notable user-facing changes to Attestrum.

Attestrum is pre-MVP (Sprint 4 of 6). No versioned releases yet. The first tagged release will be `v0.1.0` at the end of Sprint 6. Until then this file tracks landed milestones.

## [Unreleased] — pre-MVP

### Changed — `attestrum merge` emits the merged Merkle root

- **`attestrum merge` now reports the canonical root itself**: after writing the merged manifest it computes the RFC 6962 Merkle root over the canonically sorted `document_id` leaves (the identical computation `attestrum build` performs), prints it as a `merkle_root:` stdout line, and writes a `merkle.root` file beside `--out` in build's sibling-file format (64 lowercase hex chars + newline). Sharded CI pipelines — starting with the fineweb-edu sample-10BT matrix rung — consume the merged root directly instead of parsing `attestrum inspect`. The round-trip sharding test now also asserts merge's stdout root and sibling file are byte-identical to the unsharded build's; the new `merkle.root`-write error path has its own exercising test. Manifest and Merkle crate internals are untouched.

### Added — `seal-pg19`: Tier-1 deepmind-pg19 seal generator (first large rung)

- **New seal generator `crates/attestrum-pipeline/examples/seal-pg19.rs`** (with its file-walking core `examples/pg19/seal.rs`) — the third Tier-1 reference bundle after WikiText-103 and dolly-15k, and the first **large** one: PG-19 is 28,752 complete pre-1919 Project Gutenberg books, ~11.5 GB of plain text (HF `deepmind/pg19`, Apache-2.0, data in DeepMind's public GCS bucket). **One book file = one sealed leaf, exact bytes** — no render, no normalization; every leaf digest in the manifest is independently checkable against the upstream file with `b3sum`. Entries are `ContentSource::Path`, so the corpus never sits in memory (peak RAM is O(workers × largest file), max file ~4.5 MB). Per-leaf provenance is fixed: `source_type=PublicDataset`, `source_dataset_id=deepmind-pg19`, `license_spdx=Apache-2.0`, `source_uri=pg19://<split>/<id>.txt`. Determinism is gated by a seal-twice byte-identity test plus an exact-bytes CAS assertion over a fixture tree (`tests/pg19_seal.rs`); a 150-book real-data smoke seal (validation+test splits, 59 MB) reproduced its root byte-for-byte. Adds no dependency. Source pins + leaf contract: `docs/lookback/pg19-corpus-source.md`, `docs/diagrams/lookback/pg19-seal-pipeline.md`. Sealing happens in CI (gated workflows land next); canonical values pending the first capture run.
- **Gated CI workflow `.github/workflows/pg19-seal-crosscheck.yml`** (cloned from `dolly-seal-crosscheck.yml`, extended for the first large rung): an inline disk-cleanup step (stock runners guarantee only ~14 GB; corpus + CAS needs ~25–30 GB — inline `rm -rf`, deliberately not a third-party action), pinned-revision fetch + SHA-256 assert of the dataset's three file lists, `aria2c` bulk download of all 28,752 books from DeepMind's public GCS bucket with count/zero-byte assertions, and a `mode` input: `capture` bootstraps the canonical seal triple in CI (PG-19 is sealed in CI only — a laptop is the wrong machine at 11.5 GB), `assert` requires it. Download throughput, seal wall-time, peak RSS, and disk high-water land in the job summary — the Stage-2 measurements that calibrate the sharded rungs. Signs nothing, publishes nothing; `workflow_dispatch` only. **Measured** (capture run, then byte-identical assert reproduction): 11.7 GB downloaded in 754 s (14.8 MB/s), sealed in 47.6 s at ~107 MB peak RSS — canonical root `64767bab…`, 28,752 leaves.
- **Gated CI workflow `.github/workflows/pg19-publish.yml`** (cloned from `dolly-publish.yml` + the pg19 download/cleanup front-end). `workflow_dispatch`-only and **irreversible**: seals the corpus in CI, gates on the canonical triple BEFORE Fulcio/Rekor are contacted, signs the manifest keyless under the **Attestrum GitHub Actions identity** (never a personal one — §A9), publishes (`static` local artifacts or `huggingface` Hub push to `Attestrum/deepmind-pg19-sealed`), and `cosign verify`s the signed bundle asserting the `pg19-publish.yml` workflow SAN. No bundle is published until a human dispatches it.
- **PG-19 sealed bundle is LIVE**: [`Attestrum/deepmind-pg19-sealed`](https://huggingface.co/datasets/Attestrum/deepmind-pg19-sealed), published 2026-06-12 by `pg19-publish` run 27417217680 — Rekor logIndex `1803159051`, signed under the Attestrum GHA workflow identity, verified on-runner with stock cosign (`Verified OK`). The largest sealed reference corpus to date: 28,752 books / 11.7 GB, sealed + reproduced entirely in free CI. Full provenance record: `docs/lookback/pg19-corpus-source.md`.

### Added — real paste-your-own near-match is LIVE on attestrum.com

- The attestrum.com corpus-check paste box now does real client-side near-match: on an exact miss it lazy-loads the C2 wasm kernel (`attestrum-fingerprint-wasm`) + the C3 bounded corpus (`fuzzy-index.json`), computes the pasted text's 128-permutation MinHash **in the browser with the identical Rust the CLI uses**, and brute-forces exact Jaccard against the curated demo passages — rendering a discovery-grade "similarity lead" (clearly labeled NOT cryptographic proof) at ≥ 0.85. An in-page conformance check (the wasm must recompute a known corpus signature byte-for-byte) gates the path; if it fails, near-match is suppressed. Verified end-to-end on the live site: a one-word-edited member passage returns an 86% near-match. This completes Build E (C1 kernel extraction → C2 wasm + CI gates → C3 corpus artifact → C4 live integration). The CLI/repo is unchanged by this entry — it records the milestone the C1–C4 work enabled. (Landing-site code lives outside this repo.)

### Added — `fuzzy-web-gen`: tracked generator for the bounded near-match demo corpus

- **New tool `tools/fuzzy-web-gen`** produces `tests/fixtures/fuzzy-web/fuzzy-index.json` — the bounded corpus the attestrum.com client-side near-match demo matches a pasted query against. It computes each of the 5 curated showcase passages' 128-permutation MinHash with the **same PROTECTED kernel** (`attestrum-text-minhash`) the browser's wasm compiles from, so the shipped corpus signatures are byte-identical to what the browser recomputes (verified end-to-end against the C2 wasm artifact) and to what `attestrum index build` / `attestrum prove` produce. The artifact also carries each passage's display metadata (title, Wikipedia URL, snippet) and mirrors the kernel/threshold params (`sigWidth 128`, `bands 32`, `rows 4`, `jaccardThresholdPpm 850000`, `ngram 5`).
- **Reproducible + tracked.** A reproducibility test regenerates the artifact and byte-compares it to the committed golden, asserts every leaf signature equals the kernel, and asserts `snippet` is the exact byte-source of `sig` (so the upcoming in-page conformance check holds). This fills the gap that the demo's browser artifacts previously had no tracked generator. At 5 leaves (~22 KB) the browser fetches the JSON wholesale and brute-forces exact Jaccard — the exhaustive recall oracle, identical in result to the production LSH path at this size; the scalable binary index re-encoder is deferred to land with the full corpus. Not a §4 change (reads through the protected kernel, modifies nothing; the artifact is discovery-grade, not a signed/verified emitter).

### Added — `attestrum-fingerprint-wasm`: the text-MinHash kernel compiled to `wasm32`, byte-identity gated in CI

- **New crate `attestrum-fingerprint-wasm`** (workspace now 18 crates) — a `cdylib` that compiles the PROTECTED text-MinHash kernel (`attestrum-text-minhash`) to `wasm32-unknown-unknown` behind a raw `extern "C"` ABI (`attestrum_alloc` → `attestrum_minhash` → `attestrum_dealloc`, no `wasm-bindgen`, no new dependency). The upcoming attestrum.com client-side near-match demo will load this `.wasm` and compute a query's 128-permutation MinHash signature **in the browser with the identical Rust** the CLI and the sealed-corpus sidecars use — there is no second implementation that could drift from the signed proofs. The crate adds no algorithm; it only marshals bytes across the FFI boundary.
- **New CI gates (`.github/workflows/wasm.yml`), on both x86 and arm, keep the artifact honest.** A *reproducible-build* check builds the `wasm-release` artifact twice per host and `cmp`s same-host (the served `.wasm` re-verifies on its build toolchain). The load-bearing *output cross-check* runs every passage through the **actual** `.wasm` via a no-dependency Node loader (`tools/wasm-crosscheck/run.mjs`) and diffs against a golden generated from the native kernel — proving the real wasm output equals the native kernel byte-for-byte, which a native-only golden cannot. Cross-arch *binary* identity is intentionally not asserted: rustc→wasm32 is reproducible per host but not bit-identical across an x86 vs arm build host, and the artifact is built once — so the host-independent property that matters is the output, proven on both arches. `blake3`'s `pure` backend is scoped to wasm builds only (the P1 spike proved `pure` == default bit-for-bit), so native builds keep the default backend.
- **Not a further PROTECTED change** (founder-confirmed routine, 2026-06-06): the C1 extraction's §4 approval already named "byte-identical WASM reuse" as its purpose, and this crate changes no protected parameter. The cross-check CI gate — not a commit footer — is the real safeguard for the browser surface.

- `normalize_text` + the 128-permutation `minhash::compute` moved out of `attestrum-fingerprint` into a new `attestrum-text-minhash` crate (workspace now 17 crates). The move is **byte-identical** — output is unchanged for every input (the `attestrum-fingerprint` determinism + api-surface golden tests pass untouched, and the P1 spike proved the extracted kernel equals the prior build bit-for-bit, including with blake3's `pure` feature). `attestrum-fingerprint`'s public API (`fingerprint_text`, `TextFingerprint`, …) is unchanged. ### Added — `attestrum prove` now reports fuzzy match strength

- The `prove` summary prints a new `match:` line carrying the actual fuzzy metric — `MinHash Jaccard 96.1% (5-gram)`, `ISCC composite distance 3`, or `perceptual Hamming 4 (≤ 6)` — alongside the existing per-kind `confidence`. Previously a 0.85-threshold squeaker and a near-identical 0.99 match both printed only `confidence: 0.80`, hiding how close a near-match actually was; the similarity now shown is the same value the signed proof records. Exact-hash matches are unchanged (the `confidence: 1.00` line already conveys "exact"). `ProofArtifact` gains a `match_evidence: Option<MatchEvidence>` field exposing the same data to programmatic callers. CLI/output surfacing only — not a §4 change.

### Added — indexed fuzzy lookup (v1.1): `attestrum index build` + a sub-second `prove` fast-path

- **New crate `attestrum-index` + `attestrum index build` subcommand.** `attestrum prove`'s three fuzzy paths (text MinHash, image perceptual, ISCC) previously re-read and re-fingerprinted *every* manifest leaf on each query — the ~42 s/query scan that gated any interactive use. `attestrum index build --workspace <dir>` now derives a **discovery-grade sidecar index** (`<workspace>/.attestrum/index/{minhash,perceptual,iscc}/v1.idx`) that persists each leaf's fuzzy signature once. `prove` auto-detects it and, when present, gathers LSH candidates and scores only those against their stored signatures — **no CAS read, no re-fingerprinting**. Measured **~125× faster** on a 400-leaf corpus (3.3 s → 26 ms), and the speedup grows with corpus size.
- **The emitted proof is byte-identical with or without the index.** The index is a *candidate filter* only: the exact recheck (`minhash_jaccard ≥ 0.85`, `min(pHash, blockhash) Hamming ≤ 6`, ISCC composite distance ≤ 4) and the signed inclusion proof are the existing, unchanged code. Text MinHash uses band-of-perms LSH (32×4); image perceptual and ISCC use Hamming pigeonhole banding, which gives **exact recall** (zero false negatives) for distance ≤ threshold. A `--no-index` flag forces the full exhaustive scan (the recall oracle), and a missing / corrupt / stale (binding-mismatch) sidecar silently falls back to it. Each sidecar binds to its corpus via the manifest's Merkle root, so a stale index built against a different corpus is rejected, not trusted.
- **Not a PROTECTED change** (roadmap v1.1, non-§4, reversible): the index is a *derived* artifact under the reserved `.attestrum/index/` directory — no manifest schema, Merkle, predicate, or fingerprint-normalization change. It is unsigned and never part of the trust chain. The sidecar is raw little-endian and rebuilds byte-identically from the manifest + CAS (the perceptual sub-index inherits pHash's documented ≤1–2-bit cross-target drift; MinHash + ISCC are integer-only and fully deterministic). On-disk format: `docs/diagrams/index/sidecar-format.md`; build + query flows: `docs/diagrams/index/build-and-query.md`.

### Fixed — Lookback detokenizer completeness + backref attribution; corpus re-sealed

- **Detokenizer completeness.** An adversarial review + full-corpus measurement found the WikiText-103 detokenizer left a residual tokenization artifact on **39.65%** of sealed passages (dominated by spaced straight quotes, plus spaced slash, currency, digit-colons) — text a clean paste would not match, defeating the demo's "paste-to-match" purpose. The detokenizer now handles straight/`` ``/'' `` quotes, currency, digit-colon (`3 : 30` → `3:30`), spaced slash, and em-dash; the residual rate fell to **0.10%**.
- **Backref attribution.** WikiText-103 linearizes stat-table glossaries as single-`=` lines mid-article, which were mis-read as article titles — mis-attributing the following passages and producing **328** colliding `source_uri` backrefs. Those lines are now rejected as titles and colliding slugs are disambiguated; collisions are **0**. Leaf-level provenance was never affected (each leaf carried its own `source_url`).
- **Re-sealed.** The corrected corpus was re-sealed; the new canonical Merkle root is `de95bddc…696726dc` over 822,559 leaves (808,823 unique content objects). `docs/research/deterministic-by-construction.md` records the new artifact (§4.1); cross-platform reproduction of this root is the next gate.

### Added — Corpus-to-model binding (`model-binding/v0.1`)

- **New `model-binding/v0.1` attestation** closes Attestrum's keystone gap: a signed corpus proves "corpus C existed with root R", not "C trained model M". The binding is an in-toto v1 Statement with the **model as subject** and the **training-corpus attestation(s) as materials**, under `https://attestrum.com/attestation/model-binding/v0.1`. It is an **attestation, not a proof-of-training** — the cryptography guarantees integrity, timestamp, identity, and verifiable membership against the corpus, not the truth of the training claim.
- **`attestrum bind`** — emit a binding (model weights-manifest digest + one or more `--corpus`/`--role` pairs), signed via Sigstore by default (`--unsigned` to skip; OIDC via `--oidc-token-file` or `SIGSTORE_ID_TOKEN`).
- **`attestrum walk-chain`** — verify "is work X in the corpus that trained model M?". Sigstore-verifies the binding and each corpus bundle, then re-runs the membership proof live. Multi-corpus results are OR-ed ("in at least one corpus that trained M"); exits `0` on a determined answer, `6` when a bound corpus fails to verify and no inclusion was found.
- **Honest ceiling**: the chain walk *recomputes* the membership proof from the verifier-supplied manifest rather than verifying an independently-signed one — membership is only as strong as that manifest.
- New `attestrum-bind` crate (`bind()` + signed `walk_chain()`); `attestrum_attest::verify_statement()` widens verification to non-training-corpus predicate families while keeping `verify()` byte-for-byte compatible.

### Added — Verification hardening
