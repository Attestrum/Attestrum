# Migration: v0.2 → v0.3 (Attestrum rebrand)

**Type**: PROTECTED predicate URI version bump + URI host migration.
**Date**: 2026-05-24.
**Applies to**: all three PROTECTED predicate URI constants in `crates/attestrum-attest/src/lib.rs`.
**Migration scope**: theoretical-only — zero existing-bundle impact.
**Submission target**: in-toto vetted catalog at https://github.com/in-toto/attestation/tree/main/spec/predicates.

---

## What changed

| Before (Annex era, v0.2) | After (Attestrum, v0.3) |
|---|---|
| `https://annex.build/attestation/training-corpus/v0.2` | `https://attestrum.com/attestation/training-corpus/v0.3` |
| `https://annex.build/attestation/inclusion-proof/v0.2` | `https://attestrum.com/attestation/inclusion-proof/v0.3` |
| `https://annex.build/attestation/non-inclusion-proof/v0.2` | `https://attestrum.com/attestation/non-inclusion-proof/v0.3` |

Two simultaneous changes:

1. **Host migration**: `annex.build` → `attestrum.com`. The `annex.build` domain was owned by a third-party GoDaddy parking-page squatter (verified at the time of the rebrand via `dig +short annex.build` + `curl -L https://annex.build/`). The founder bought `attestrum.com` outright to avoid permanently entrusting predicate URI authority to a domain they did not control.
2. **Version bump v0.2 → v0.3**: any change to the URI host is a contract-breaking change for verifiers. The version increment makes the host change explicit and clean.

**No field-level schema changes.** The Rust struct shapes in `crates/attestrum-attest/src/predicate.rs` (`TrainingCorpusPredicate`, `InclusionProofPredicate`, `NonInclusionProofPredicate`) are byte-for-byte identical to the Annex-era v0.2 shapes. The 10 `u32` parts-per-million fields in `SignalCoverage` (9) + `MinHashEvidence.jaccard` (1) carry forward unchanged — they were established at the Annex-era v0.1 → v0.2 bump for cross-target byte determinism.

## Why v0.3 and not v1.0

Bundling the host migration with the field-level v0.1 → v0.2 PPM bump (which was justified by cross-target determinism) would have conflated two unrelated changes. Bumping host without bumping version would have left two URIs (`annex.build/.../v0.2` and `attestrum.com/.../v0.2`) referring to the same schema — a verifier matching on URI prefix would treat them as distinct contracts. Bumping major version (v0.2 → v1.0) implies "first stable release," which the project has not yet earned (no in-toto vetted-catalog acceptance yet, no design partners committed, no Aug 2 2026 enforcement-date demo shipped).

v0.3 cleanly says "next iteration, breaking only because of host migration, otherwise byte-shape-identical to v0.2." When the predicates earn first stable release (post-design-partner ship + in-toto vetted-catalog acceptance), the bump to v1.0 will signal that to the ecosystem.

## Zero existing-bundle impact

`attestrum prove` (the verifier that would consume these predicates in a real bundle) has never shipped publicly. No bundle with `annex.build/...` URIs was ever signed by a real OIDC identity through a Sigstore-rs production verifier (the Annex-era `annex sign` only generated test-fixture bundles, never a production-signed corpus).

The v0.3 launch under the Attestrum project name is therefore a clean predicate-namespace start. No verifier in the wild needs to migrate. No published bundles need to be re-signed. The in-toto vetted-catalog PR opens directly with the v0.3 URIs at attestrum.com; no v0.2 catalog submission was ever made.

## Verifier guidance

Anyone who built a verifier against the never-published Annex `annex.build/.../v0.2` URIs (which would be unusual — there were no public consumers — but for completeness):

1. Update predicate URI matching from `annex.build/attestation/{training-corpus,inclusion-proof,non-inclusion-proof}/v0.2` to `attestrum.com/attestation/{training-corpus,inclusion-proof,non-inclusion-proof}/v0.3`.
2. No struct-shape changes required. Existing `TrainingCorpusPredicate` / `InclusionProofPredicate` / `NonInclusionProofPredicate` deserializers continue to work.
3. JSON-Schema URIs follow the same shape: `https://attestrum.com/attestation/<kind>/v0.3.schema.json`. Schemas are served via Netlify static site at attestrum.com (deploy timing: founder action, post-rebrand).

## Migration is atomic

In the Attestrum repo, the v0.3 launch is the Initial commit. There is no v0.2 schema in attestrum/'s `docs/schemas/` (those were renamed during the migration); there is no `annex.build/.../v0.2` URI in any attestrum/ source file (mechanically swept). The v0.3 set IS the inaugural set under the Attestrum project name.

The Annex-era v0.1 and v0.2 schemas survive only in the frozen historical Annex repository (local-only), where they are preserved as the development lineage that produced the v0.3 contract.
