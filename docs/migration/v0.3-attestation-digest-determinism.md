# Migration: v0.3 `attestationDigest` determinism correction

**Type**: PROTECTED predicate **value-semantics** correction — NOT a schema-shape change, NOT a URI version bump.
**Date**: 2026-05-29.
**Applies to**: `corpus.attestationDigest` in the `inclusion-proof/v0.3` and `non-inclusion-proof/v0.3` predicates (`crates/attestrum-attest/src/predicate.rs` `CorpusRef`), as populated by `attestrum-prove::prove()`.
**Migration scope**: theoretical-only — zero existing-bundle impact (see "Why no bundles are affected").
**Submission target**: in-toto vetted catalog at https://github.com/in-toto/attestation/tree/main/spec/predicates (the proof-predicate submission, which has **never been made** — see below).

---

## What changed

`CorpusRef.attestationDigest` has always been **documented** (`predicate.rs` doc-comment) as "the digest of the corpus's signed in-toto Statement (the bundle's DSSE payload)." The implementation in `prove()` instead hashed the **whole corpus bundle file** (`attestrum_cas::stream_hash_path`). For a signed Sigstore Bundle v0.3 that file carries 16 non-deterministic fields (Fulcio cert chain, Rekor tlog entries, `integratedTime`, `logIndex`, the DSSE signature, the ephemeral public key — the `canonicalize::STRIP_PATHS` set). Hashing the whole file therefore produced a **different `attestationDigest` on every signing of the identical corpus Statement** — non-deterministic, which CLAUDE.md §7 classifies as a bug.

The fix introduces `attestrum_attest::attestation_digest_of_bundle(path)` and routes both `prove()` call sites through it. The value is now the BLAKE3 + SHA-256 of the corpus Statement's `canonical_json()` (DSSE-payload) bytes — deterministic, and identical whether the corpus is signed or unsigned. The helper re-emits `canonical_json()` on both the signed and raw branches, so a corpus signed by stock `cosign` (whose embedded payload need not be key-sorted) still produces the canonical digest.

| | Before | After |
|---|---|---|
| **Definition** | (documented) DSSE-payload digest | DSSE-payload digest |
| **Implementation** | whole bundle **file** hash (`stream_hash_path`) | canonical Statement bytes hash (`attestation_digest_of_bundle`) |
| **Determinism when signed** | ❌ different per signing | ✅ stable |
| **Schema shape (`DigestMap {blake3, sha256}`)** | unchanged | unchanged |
| **Predicate URI** | `…/inclusion-proof/v0.3` | `…/inclusion-proof/v0.3` (**unchanged**) |

## Why this is a v0.3 amendment and NOT a v0.4 URI bump

CLAUDE.md §4 requires a version bump for "a change to the URI string OR the JSON-Schema shape of any predicate payload." This change is **neither**:

- **The schema shape is byte-identical.** `CorpusRef` stays `{manifestUri, merkleRoot, attestationDigest: {blake3, sha256}}`. The `schemars`-derived `docs/schemas/{inclusion,non-inclusion}-proof-v0.3.schema.json` files are unchanged (the `schema_derive` test stays green, which is the mechanical proof that the shape did not move).
- **It is a determinism bugfix to a field value, not a contract change.** This is explicitly **not** the "backward-compatible v0.3 amendment" clause in `tests/schema_derive.rs` — that clause is scoped to *shape* changes ("v0.3 validators continue to accept the new shape"). This change is a **value** correction, recorded here so the precedent is honest: a previously-non-deterministic field is being given a deterministic definition that matches the type's long-standing doc-comment.

## Why no bundles are affected

The old value was non-deterministic for signed bundles, so no verifier in the wild could have pinned a stable `attestationDigest` to re-derive against. Concretely:

- **No signed `inclusion-proof/v0.3` or `non-inclusion-proof/v0.3` bundle has been published externally** (confirmed 2026-05-29). Attestrum is pre-MVP; the proof predicates' payloads were only first populated in Sprint 5.
- **The in-toto vetted-catalog submission for the proof predicates has never been made** — it opens only once `attestrum.com` serves the schemas. This determinism correction therefore lands **before** any catalog submission, ensuring the submitted spec does not describe a field that violates Attestrum's own determinism invariant.

## Verification

- `attestation_digest_of_bundle` unit tests (`crates/attestrum-attest/src/corpus_digest.rs`): signed-bundle payload == raw-Statement digest; a non-canonical (cosign-style) payload still digests equal; junk files are rejected.
- `corpus_bundle_path_populates_attestation_digest` (`crates/attestrum-prove/tests/sign_integration.rs`): `prove()`'s emitted digest equals the helper's, over a real corpus Statement.
- `schema_derive` stays green — proves the shape did not change.
